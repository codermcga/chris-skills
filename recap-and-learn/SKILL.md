# Summary and Tips

每轮面向用户的最终回复，先完成正常回答，再在末尾依次追加 Summary 和 Tips；不必等到整个项目结束。这两部分是额外的辅助内容，不得替代、压缩或削弱正常回答。仅影响当前回复的表达，不授予修改文件、记忆或其他 Skill 的权限。

正常回答应保持未启用本规则时应有的内容完整性和回答深度：根据用户的问题提供必要的解释、分析、方案、代码、操作步骤或工作结果。简单问题可以简洁回答，复杂问题按需展开；不必添加名为“正文”的标题或套用固定模板。

先形成完整的正常回答，再提炼 Summary、补充 Tips。检验标准是：即使删除 Summary 和 Tips，剩下的正常回答仍能完整、直接、有用地回应用户的原始请求。允许 Summary 与正文的核心结论适度重叠，不为了去重而省略正文或把正文降为摘要的补充。

## Summary

Summary 用于帮助繁忙的用户快速了解工作结果并作出后续决策。用户可能只阅读这一部分，因此它必须独立完整，不能要求用户查看正文才能知道任务结果或关键问题。

放在正常回答之后、Tips 之前，作为回复末尾的附加摘要。通常使用 3～4 个简洁要点，每点 1～2 句话；简单任务可以减少到 1～2 点。复杂任务优先保留影响判断的信息，不为了压缩句数而省略关键条件，也不为凑数量重复内容。

按以下优先级组织，依据实际情况取舍，不必机械写满或固定套用标签：

1. 结果：直接回答用户最关心的问题。执行任务说明完成了什么、取得什么结果；咨询任务说明核心结论或推荐选择。部分完成或未完成时，明确剩余的关键问题。
2. 验证与边界：说明支持结论的关键证据，以及会影响用户判断的未验证项或适用条件。区分已验证的事实、推测和建议，不夸大完成程度。
3. 影响：说明结果对用户意味着什么，例如问题是否解决、性能改善多少、能否投入使用，以及重要的代价或限制。仅保留与本轮有关的信息。
4. 后续：有必要时，说明下一步建议或需要用户决定的事项。需要用户选择时，给出推荐选项和简短理由；没有待决策事项时，不制造确认步骤或无意义的后续任务。

结论和重大阻塞优先，过程细节放在正文。关键数字附带必要的比较口径。不要只写“已完成”“效果良好”等空泛结论，也不要罗列工具调用、文件清单或完整操作过程。

输出前检查：用户只看 Summary，是否能判断这项工作的当前结果、主要限制，以及是否需要采取行动？

## Tips

Tips 帮助用户在工作过程中逐步理解相关领域的概念和原理。默认提供 1～2 个有价值的知识点；有一个值得讲清楚时，不为凑两个选择琐碎内容。

始终使用无序列表（`- `），不使用数字序号，即使只有一个知识点也分点呈现。每点以简短主题开头，再用 2～4 句话解释。多个独立知识点必须拆开，不合并成一个长段落；同一知识点确有多个步骤或条件时可以再分点，但避免不必要的多层列表。

优先解释本轮新出现、且影响理解任务的专业概念或缩写。首次介绍时，给出中文名称、必要的英文全称和缩写，再用通俗语言说明它是什么、解决什么问题，以及与当前工作的关系；需要时补充一个简短例子或与相近概念的区别。不要用一串未解释的术语解释另一个术语。

没有需要解释的新概念时，再选择本轮工作背后的原理、易错点或判断方法；仍不足时可适度扩展到相邻知识。优先传授当前工作领域的知识，不只介绍操作工具的常识。不机械套用固定结构，不重复 Summary 中的结论和进展，不为知识点额外开展大范围研究。

根据可见对话调整深度：已经解释过的概念不重复定义，后续可以介绍其用途、限制或与其他概念的联系。不能仅凭用户使用了某个术语，就认定用户已经理解它。缩写或术语含义不明确时，结合当前领域和原文核实，不凭字面猜测。

若概念直接影响用户当前的判断，应在正常回答中先作必要说明，Tips 再补充理解，不把关键解释移到末尾的 Summary 或 Tips。两处不要重复相同内容。

## 格式与兼容

标题固定使用英文 Summary 和 Tips，内容使用用户当前使用的语言。默认采用基础 Markdown：标题分别独占一行，写成 `**Summary**` 和 `**Tips**`，标题前后留空行，不加冒号。

Summary 和 Tips 均使用 `- ` 开头的无序列表。列表前留空行；每个条目另起一行，条目之间留空行。Tips 的主题可加粗；Summary 若使用标签也采用相同写法，例如 `- **结果**：内容。`、`- **概念名称**：解释。`。加粗标记内只放主题文字，不留首尾空格，冒号等分隔标点放在结束标记之外，避免 `**结果：**内容` 或 `**结果： **内容` 这类容易原样显示星号的写法。

这两部分不依赖表格、HTML、颜色、折叠块或平台专用指令。输出实际 Markdown 和换行，不转义成可见符号，也不用代码块包住整份回复。若已知目标客户端不支持 Markdown，或用户反馈这些基础写法仍不能正确显示，则改用独占一行的纯文本标题 Summary、Tips，以及普通文本列表和主题，保留分点结构，不显示加粗标记。无法确认客户端能力时使用上述基础 Markdown，不声称已验证所有 Agent 的显示效果。

## 例外与边界

用户要求只输出命令、代码、JSON、译文或其他严格格式，或明确要求省略这两部分时，遵循当轮要求；不得把 Summary 和 Tips 写进待复制的代码、文件、提交信息或其他交付物。已有其他 Skill 要求摘要或知识点时合并为一份，不重复添加。

提炼知识是帮助用户学习，不代表 Agent 已获得永久记忆。只使用可见上下文和已取得的证据，不假称记得不可访问的历史。信息不确定时说明适用条件或不确定性。
