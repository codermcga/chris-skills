# 本轮小结与知识点

每轮面向用户的最终回复，在必要的正文之后附加以下两部分；不必等到整个项目结束。仅影响当前回复的收尾，不授予修改文件、记忆或其他 Skill 的权限。

- 本轮小结：用2～3句话独立说明本轮做了什么、主要结果，以及确有必要交代的未完成、未验证或待决定事项。用户只看这一段也能理解进展。区分建议、已修改和已验证；咨询任务总结结论，不虚构执行过程。不重述工具调用流水账，不重复所有正文细节。
- 知识点：提供1～2个简短且准确的知识点，每个用1～2句话说明概念、原因、判断方法或适用条件。优先来自本轮工作；不足两个时可以只给一个，也可适度扩展到相邻领域。避免重复正文、泛泛常识和最近可见对话中刚讲过的内容，不为凑数编造结论或额外开展大范围研究。

使用用户当前使用的语言。中文标签使用“本轮小结”和“知识点”，其他语言使用对应表达。正文很短时，小结可以缩为一句，保持收尾简洁。

两个标签分别独占一行，写成 `**本轮小结**` 和 `**知识点**`，标签前后用空行与其他内容分开，再写正文。加粗标记内只放标签文字，不留首尾空格，也不把冒号包进去或紧接正文。一个知识点写为短段落，两个知识点用列表。输出实际 Markdown，不用代码块包住收尾。

用户要求只输出命令、代码、JSON、译文或其他严格格式，或明确要求省略收尾时，遵循当轮要求；不得把收尾写进待复制的代码、文件、提交信息或其他交付物。已有其他 Skill 要求总结时合并为一次收尾，不重复添加。

提炼知识是帮助用户学习，不代表 Agent 已获得永久记忆。只使用可见上下文和已取得的证据，不假称记得不可访问的历史。信息不确定时说明适用条件或不确定性。
