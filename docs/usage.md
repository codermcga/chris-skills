# 接入与更新说明

## 给新环境的 Agent

先读 README.md 的内容分类。这里提供通用指令内容，由你根据实际 Agent 和环境选择加载方式，不需要运行本仓库的安装脚本。

- **常驻提示词：**将 `recap-and-learn/SKILL.md` 的 YAML 头之后的 Markdown 正文，合并到你的用户级常驻指令／全局规则中。不要复制 YAML 头或把整个 README 当作用户全局规则。
- **全局 Skill：**将需要的 Skill 完整目录接入用户级 Skill 加载位置；保留脚本、引用与支持的元数据。`evolution` 仅允许手动触发，接入其他 Agent 时保持这个语义。
- **仓库说明：**`AGENTS.md`、`CLAUDE.md`、`.trae/rules/repository.md` 是不同 Agent 在本仓库工作的阅读入口，不是需要装到所有业务项目的能力。

Codex 通常通过全局 `AGENTS.md` 接收个人常驻指令，Claude Code 使用用户级 `CLAUDE.md`，TRAE 提供全局规则与全局技能设置。具体路径、覆盖关系和导入方式以目标环境实际版本为准；必要时查其官方文档，不照搬另一台机器或另一种 Agent 的路径。

使用 Agent 实际运行的用户和环境。若 Agent 在本机运行、仅通过 SSH 执行服务器命令，配置属于本机；Windows、WSL 和服务器也可能是不同的配置环境。用户需要跨项目使用时，不要只添加项目级规则后声称已全局生效。

保留现有配置，先比对再合并。收尾规则只保留一份；已有规则包含相同要求时直接对齐，不重复追加。需要便于后续更新时，可以给这部分内容加上来源注释，例如：

```markdown
<!-- chris-skills:recap-and-learn:begin -->
（这里放 Skill 正文）
<!-- chris-skills:recap-and-learn:end -->
```

旧版本通过安装器接入的这些标记块和 Skill 仍可继续使用；后续由 Agent 对比仓库更新，无需再运行旧脚本。原有来源标记与备份不代表新的接入依赖它们。

完成后说明改了什么、实际接入位置，以及是否需要新开会话。确认内容已写入与确认 Agent 实际加载是两件事：能验证时，用普通任务检查小结与知识点，用“只输出 JSON”检查格式例外；尚未验证的部分如实说明。

## 仓库更新后同步到当前环境

读取仓库最新版本，与本地已接入的对应提示词和 Skill 比较。确认来源、内容变化和本地改动后，更新对应内容，保留无关配置；只在出现影响用户意图、无法合理判断的冲突时询问。不需要每次重复确认已有授权。

仓库已删除或改名的内容，先检查本地引用与用途，再同步处理，避免长期残留同名旧副本。读取最新仓库或 `git pull` 只是取得源码；如果本地是独立副本，还需要实际同步。其他机器由那里的 Agent 接到更新请求时处理，不宣称当前动作已同步所有机器。

## 将新经验维护回仓库

用户要求更新通用内容时，先检查已有 Skill 和规则，优先修改对应源码；独立的新能力才建立新的 `<skill-name>/SKILL.md`，并在 README 的能力表中说明用途和触发方式。新增常驻偏好则注明内容来源及适用范围，已有 Skill 正文能复用时不再抄一份。

项目逻辑、临时路径和机器差异留在相应项目或本地配置。根据实际改动检查规则是否重复、触发方式是否冲突、引用是否有效；存在脚本时再运行适当的验证，不为说明文字增加安装框架或测试工程。

按用户授权完成修改、提交和推送，简述变化与验证。同步当前环境需另行落实；需要持续生效的规则应写入目标 Agent 的常驻入口，不能仅靠本轮读过一次来代替。
